# PROD-001 — джерела балів, рівні й ліміти точок (B3.7 + B3.2; ADR-010/011/012/013/019)

> Узгоджено з кодом `main` 2026-11-25 (агент, docs/agent/BACKLOG.md → PROD-001). Попередня версія цього
> файла (2026-11-11) писалася до трофеїв, аватарів і серверних рівнів; нижче — що з неї вже зроблено, що
> змінили пізніші ADR і що лишилось, розбите на три PR. Правда — у `docs/DECISIONS.md`.

## 0. Навіщо
`users.rating` досі завжди 0: немає жодного джерела балів. Через це ніхто не росте рівнем (ADR-013), не
відкриває аватари вищих рівнів (ADR-021 §21.7), не може створити публічну точку (поріг «Лісовик») — на
карті немає чужих точок.

## 1. Що вже є (звірено з кодом)

| `v1-me` → рівень і підказка | ✅ `level { id, label, from, to, next_label, progress_label }`; бали й прогрес бачить лише власник (чужий профіль — без балів, PR #107) |
| Аватари за рівнем | ✅ `avatars.ts` відкриває за `levelOf(rating)` — запрацює, щойно з'являться бали |

Не плутати з трофеями (ADR-021 §21.10): «підтверджена знахідка» для трофеїв рахується окремо
(`trophy_finds`, одне місце за день, ≤ 5/добу) і на бали не впливає.

## 2. Рішення, прийняті при узгодженні
- **Одне правило рівнів у двох місцях.** Відображення — `levelOf` (TypeScript, як зараз); для лімітів у
  БД — SQL-функція `public.level_of(rating INT, certified BOOLEAN) RETURNS TEXT` з **тими самими** межами.
  Розбіжність ловлять тести меж в обох мовах (0/50/51/200/201/500/501/1000/1001, з сертифікатом і без).
- **Сертифікат знань:** лише колонки `users.knowledge_certified_at`, `users.curriculum_version` (видаватиме
  B3.10). `v1-me` передає `certified = knowledge_certified_at IS NOT NULL` у `levelOf`.
- **Тиждень** — ковзні 7 діб (`now() - interval '7 days'`); «за київським часом» з плану 11.11 для ковзного
  вікна нічого не змінює.
- **Pro** — окремо (B6.3); тут лише безкоштовні ліміти.

## 3. PR-и

### PROD-001a — сервер: журнал балів і перше джерело (міграція + SQL-тести)
- `public.rating_events (id, user_id → auth.users ON DELETE CASCADE, delta INT, reason TEXT CHECK in
  ('pick_exif'), pick_id UUID NULL, created_at)`; RLS увімкнено, читання — лише свої, запис — лише
  service_role / SECURITY DEFINER-функції. Тригер AFTER INSERT: `users.rating = greatest(0, sum(delta))`.
- `users.knowledge_certified_at`, `users.curriculum_version`.
- `public.level_of(rating, certified)` — див. §2.
- `create_pick(...)` + параметр `p_exif_verified BOOLEAN DEFAULT false`: приватна точка з успішною
  EXIF-перевіркою → подія `pick_exif +1`, **не більше 5 за 7 днів** (ADR-012 №3, ADR-019 §19.10); в одній
  транзакції зі вставкою, під наявним блокуванням користувача.
- `can_create_pick` за ADR-019 §19.10:
  - публічні: нижче «Лісовика» → `level_required`; Лісовик — **7 за 7 днів**, Хранитель лісу — **15**
    (`weekly_limit_reached`);
  - приватні: **до 5 одночасно** (не видалені) → `private_limit_reached` («видаліть одну»), і **≤ 10 нових
    за 7 днів** → `weekly_limit_reached`.
- Нові функції — `SECURITY DEFINER`, `search_path` зафіксовано, `REVOKE … FROM PUBLIC, anon, authenticated`
  (інакше впаде `security_definer_privileges.sql`).
- SQL-тести (новий `supabase/tests/rls_rating.sql`): сума журналу й нижня межа 0; межі `level_of`;
  +1 лише 5 разів за 7 днів і лише для приватних з EXIF; клієнт не пише в журнал; 6-та приватна →
  `private_limit_reached`, після видалення — знову можна; Слідопит не публікує; Лісовик — 7, Хранитель — 15.
- Перевірка: `scripts/dev/local-db/run.sh`, CI-job `migrations`.

### PROD-001b — API: `v1-picks` передає EXIF, `v1-me` віддає дозволи
- `v1-picks`: `p_exif_verified = ai_check.exif.verified` у виклику `create_pick`.
- `v1-me`: `certified` у `levelOf`; `picks: { public_allowed: bool, public_hint_label: string | null,
  private_left: int }` — сервер вирішує, клієнт лише показує (гість → «після входу»; рівень → скільки балів
  до Лісовика; ліміт → коли звільниться).
- OpenAPI (`openapi/v1.yaml`) + контракт моделей Flutter (QA-003 CI) + Deno-тести (гість, Мандрівник,
  Лісовик на ліміті).

### PROD-001c — Flutter
- `Me.picks`; форма тук-тука: «Усі» вимкнено, коли `public_allowed == false`, під ним `public_hint_label`;
  кнопка на карті — «Приватний тук-тук» (ADR-018 §18.2), якщо ще не так.
- Профіль: бали ростуть — прогрес рівня вже показується (нічого не міняти, лише тест на нові поля).
- Тести віджетів + стрес-тест розмітки (test/a11y) для форми.
