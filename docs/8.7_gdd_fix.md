# 8.7 GDD Fix — Graceful Degrade

## Проблема

`computeGDD` (`supabase/functions/_shared/forecast/weather.ts`) дає
**37-денне ковзне вікно** (`past_days=30` + `forecast_days=7`),
а `GDD_THRESHOLDS` (`constants.ts`) — **кумулятивна шкала з 1 січня**
(`spring:150, summer1:450, summer2:900, autumn:1500, late:2100`).

Порівняння цих двох величин некоректне:

- реальний GDD у жовтні (ковзне вікно) ≈ 230
- порог `autumn:1500` недосяжний за будь-якого ковзного вікна
- `detectWave` деградував у `previousWave(autumn) = summer2`

Симптом (12.10.2026): `POST /forecast {lat:50.45, lng:30.52}`
→ `wave: "summer2"` замість `"autumn"`; види з
`peak_waves=['autumn']` (білий) не отримували peak-бонус.

Семантичний місметч: жоден набір порогів не сумісний з ковзним
вікном — у листопаді ковзний GDD буде МЕНШЕ, ніж у жовтні, тому
`late:2100` недосяжний за принципом.

## Рішення (8.7a, 2026-10-12)

- `detectWave` повертає `calendarWave` завжди; GDD-аргумент
  збережено в сигнатурі для сумісності з `ContextBuilder`, але
  проігнорований (`void gdd`).
- `previousWave` не викликається, але залишається експортованим
  (може знадобитись для V2).
- `GDD_THRESHOLDS` позначено `DEPRECATED (8.7a)` — активується
  разом із кумулятивним GDD.
- `previousWave` + `WAVE_ORDER` не змінені.

## Ticket V2 (9.x): Кумулятивний GDD

- Джерело: open-meteo **archive** endpoint
  (`start_date=01-01` поточного року, `end_date=сьогодні`),
  `daily=temperature_2m_max,temperature_2m_min`;
  або: окрема таблиця `gdd_state` (`region_id`, `date`, `gdd`)
  + cron щодня о 03:00 UTC.
- Кумулятивна шкала (план v6.0 §11.3, до перекалібрування):
  `spring=50, summer1=350, summer2=700, autumn=1100, late=1400`.
- Потрібен кеш (nginx/edge cache): latency archive endpoint ~2–3 с,
  що ламає cold-start бюджет Edge Function.
- Разом із V2 розібратись із `flags.gdd_enabled` — зараз мертвий
  (не використовується ніде; після 8.7a тим паче).

## Пов'язані tickets

1. `gdd_enabled` — мертвий прапорець у `FeatureFlags`. Або
   прив'язати до кумулятивного GDD (V2), або видалити з
   `feature_flags` + типу.
2. Після впровадження — повернути GDD-крок у `detectWave`
   та зняти `DEPRECATED` з `GDD_THRESHOLDS`.
